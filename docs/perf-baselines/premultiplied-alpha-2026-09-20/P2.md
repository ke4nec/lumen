# P2：CPU 预乘累积与图片缓存

基点 `ea8a0c3`。CPU 帧与绘制缓存改为 Premultiplied / Opaque，删除 P1 直通缓存桥接。公共 Color、Theme、几何、覆盖率和最近邻采样保持原契约。

## 实现与 review

直通颜色先把 coverage 折入有效 alpha，再生成预乘源；图片上传只归一化一次，绘制时额外 clip coverage 同时缩放 RGB 与 A。公共标量 source-over 使用集中定义的 mul255，保留透明跳过、不透明覆写和 span 快速路径；不再乘目标 alpha 或除以输出 alpha。

完整与 damage 清屏使用同一预乘字节。不透明完整清屏建立 Opaque 证明，Preserve 继承证明；不能从局部绘制推断整帧不透明。`pixels()` 返回实际已发布缓冲，无隐藏转换。

review 修复了“配置失效”和“已发布帧”混用的问题：改变 clear/DPI 后仍能读取上一个完成帧，但下一次 Preserve 必须退回完整绘制。绘制中改变配置也不能使刚发布的旧配置帧被再次复用。双缓冲只复制 damage band 时同步模式。新增回归覆盖这些状态及三个 DPI、三类 clear alpha 下连续六帧的 full/partial 精确等价。

## 验证

- CPU Release 全量 CTest 754/754（`build-alpha-after/ctest-p2.log`），CPU Debug 754/754（`build/ctest-alpha-p2.log`）。
- GPU Release 775/775，无跳过（`build-gpu/ctest-alpha-p2.log`）；Skia raster Release 765/765（`build-alpha-skia-after/ctest-p2.log`）。
- 定向 alpha 回归 18 用例、172,875 断言；独立整数模型覆盖层叠，Color/图片入口分别检查边缘 RGB<=A 和纯红 R=A。
- `images` 与 `upload` 原始帧逐字节等于 P0 冻结的独立参考，SHA256 `b9c0993e08149dbcde46a3d79b6aac8e8366deef1195d93cfa0b13ae9fd4cc36`；旧通道回绕竖条消失，未修改参考算法或采样规则。
- layers / edges 与 P0 统一为预乘后，最大 RGBA 差都是 `[1,1,1,0]`，超差像素 0。
- 42 个 Gallery 样本 alpha 完全一致，RGB 差都在 P0 冻结的 4 级范围内，超差像素 0。逐张模式、SHA256 与空间差异结果见 [P2-gallery-comparisons.json](P2-gallery-comparisons.json)。实际图在 `build-alpha-after/p2-gallery`，包括 alpha/黑/白/棋盘与差异图。检查标题栏 hover、透明圆角和图片样本未发现新增暗边或几何漂移。
- Windows CPU software / texture、透明 / 不透明四条正常路径均为 0 次转换、0 复制字节、0 scratch；原始探针 `build-alpha-after/p2-frames/window-probes.json`。与构建并行的短探针仅证明路径和像素，不作为性能结论。

命令：`cmake --build <目录> --config <配置> --parallel 4`；`ctest --test-dir <目录> -C <配置> --output-on-failure --parallel 6`。raw 用 `lumen-alpha-bench --dump-frame` / `lumen-alpha-gallery` 生成；比较遵守 `alpha_frames.py` 的预乘表示与既定误差预算，Gallery 批处理用本机 NumPy 加速同一计算（未新增项目依赖）。

本阶段不更新既有控件哈希，不改写 before 构建和历史基线。Skia Preserve、跨后端与宿主透明能力留到 P3；完整系统字体/跨后端视觉和交错性能验收留到 P4。
