# P1：明确格式并贯通消费者

基点 `a28c26f`。P0 的两个 before 构建与原始帧保持冻结；本阶段 CPU 帧仍是直通，旧通道回绕刻画保留到 P2。

## 接口与边界

- `PixelBuffer` 尾部增加 `AlphaMode`（Straight=0、Premultiplied=1、Opaque=2），默认直通；相等性包含模式，frameHash 仍只处理尺寸和字节。公开布局改变，使用方须重编译。
- 转换返回 bool，支持原地/别名、重复调用、目标容量复用；错误内容不改变目标。默认验证预乘 RGB<=A / Opaque A=255；`PixelValidation::Structure` 只用于生产者已保证内容的内部数据。不把低 alpha 的反预乘当成无损往返。
- ResourceManager 保存原始模式与设备重上传数据；文件解码显式为直通。CPU 两个上传入口共用转换帮助函数，在 P1 临时转换到直通缓存，P2 删除此兼容分支。
- Skia raster/GPU 按输入模式映射 alpha type；raster 通过默认回放钩子按顺序消费资源命令，不能在整帧绘制前预先处理所有上传。raster 读回为预乘，只有不透明全量清屏及保留该证明的 source-over 帧标记 Opaque。
- SDL 两条路径实现六种模式组合，直接路径不创建或保留转换副本；兼容路径复用 scratch，回到直接帧时释放。每次 present 只有 O(1) 结构检查。纹理统一 NONE，外部半透明直通输入在不透明窗口保持 RGB，修复旧默认 BLEND 的不一致。
- Gallery 两个默认 raw 导出入口显式转换到直通，写入 width/height/alpha_mode；benchmark 原始帧记录实际模式。命令写 v7、读 v6/v7，模式在磁盘是 u32；非法模式（包括 256）、长度、像素内容、未知版本、截断均拒绝且不部分覆盖输出。无效像素的序列化返回空串。

## Review 与证据

review 修复 Skia 复用 paint 导致图片继承上一条形状 alpha 的问题；图片自身 alpha 不再额外乘旧 paint alpha。即时注册与显式命令 ID 共用缓存时跳过已存在 ID；非法覆盖保留上一次有效资源；readPixels 失败不发布伪 Opaque 零帧。解码、输出元数据和标题栏/视觉系统中的当前版本说明同步更新。

GPU 全量门槛另暴露既有 List 测试夹具遗漏：`99d364b` 已把焦点环默认改为关闭，该测试仍按开启后的 marker inset 与焦点环颜色取样，因而独立重跑也有 6 个断言失败。本阶段仅把该夹具改成显式 `withFocusRing(..., true)`，并断言布局环宽有效，保持其原有可见焦点测试意图；未改 List 绘制或主题值。

独立转换回归遍历 65,536 个直通通道/alpha 组合与全部 32,896 个合法预乘通道/alpha 组合，另覆盖别名、幂等、复用、非法内容和不透明证明。冻结的 v6 fixture 来自 P0 真实记录，仅将尺寸与图片缩到 1×1，完全独立于 v7 写入器。CPU/Skia 回放验证同 ID 替换、非法替换、卸载及图片不继承 shape alpha；GPU 增加独立 GL 读回回归。

已运行 CPU Release 全量 CTest 749/749、Skia raster Release 760/760，CPU Debug 749/749；CPU `[alpha]` 13 用例 / 107,944 断言。日志在 `build-alpha-after/ctest-p1.log`、`build-alpha-skia-after/ctest-p1.log`、`build/ctest-alpha-p1.log`。构建命令为 `cmake --build <目录> --config <配置>`，测试为 `ctest --test-dir <目录> -C <配置> --output-on-failure --parallel 6`。GPU Release 修复夹具后全量 770/770，无跳过；日志 `build-gpu/ctest-alpha-p1-final.log`。新增真实 GL 图片模式读回独立运行 20/20 断言通过（`build-gpu/alpha-p1-gpu.log`），未引入生产 GPU 读回。

CPU 三个 canonical 场景及 CPU/Skia 四个固定 alpha 场景，共 11 个帧哈希与 P0 精确一致；原始核对在 `build-alpha-after/p1-probes/hash-checks.json`。两个 Gallery raw 导出实际运行，元数据为 straight，字节长度与尺寸一致。

真实 Windows 探针见 [P1-window-probes.json](P1-window-probes.json)：Skia software 红色由 P0 的 64 恢复到 128；software / direct3d11 texture 均为 0 次 Lumen 转换、0 字节 scratch。CPU 仍为直通，透明呈现转换一次、1080p scratch 8,294,400 字节。此处 warmup=1/frames=3，与构建并行，只作为正确性探针，不使用耗时判断收益。Windows software surface 仍为 XRGB8888、A=255；P3 必须明确原生透明能力限制。

P1 不改变 CPU 几何、采样或累积算法。正式同机配对性能比较留到 P4；Linux/macOS、GPU 故障恢复的模式保真及完整真实窗口生命周期留到 P3。

P1 阶段 review、修复和对应全量门槛完成，出口满足。下一阶段迁移 CPU 累积与图片缓存，删除 P1 直通桥接，并将旧通道回绕刻画改成正确结果断言。
