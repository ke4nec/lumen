- SDL3 `release-3.2.10`（`877399b2b2cf21e67554ed9046410f268ce1d1b2`），Catch2 v3.8.1（`2b60af89e23d28eefc081bc930831ee9d45ea58b`），stb `2c980bb59875b0d32144a71867fbdebb2f77cd20`；Skia m124 固定 Windows Release 包，zlib v1.3.1。

- 配置均启用 tests/examples/benchmarks，GPU=OFF；Skia 仅后一构建为 ON。依赖通过 `FETCHCONTENT_SOURCE_DIR_*` 指向本机已核对的固定版本，完整 CMakeCache、二进制 SHA256 和采样命令保存在忽略目录的 manifest。

## 最小复现与预先固定的规则

`lumen-alpha-bench --scenario probe --backend cpu|skia --present software`：
透明底绘制 `(255,0,0,128)`。CPU 原始像素为 `(255,0,0,128)`，Windows 软件表面 RGB 为 `(128,0,0)`；
Skia 原始像素已为 `(128,0,0,128)`，同一呈现路径的软件表面 RGB 为 `(64,0,0)`。
这是实际窗口源字节及目标表面读回的二次预乘证据，不是通过注释推断的视觉结论。
该软件表面为 `SDL_PIXELFORMAT_XRGB8888`、读回 A=255，P3 必须继续核对原生表面/系统合成器能力；不能将此结果当作透明桌面合成通过。4K 窗口的实际 drawable 为 3840×2160，虽然本机显示器只有 1920×1080；这是完整 4K surface 的上传/提交测量，不是整块 4K 屏幕的目视验收。

`alpha_reference_tests.cpp` 使用独立浮点乘法取整的整数参考模型及双精度 source-over，
不调用生产转换/混合函数。1024 组固定输入、每组八层，覆盖 A=0/1/2/127/128/254/255；
P0 实测最大整数模型差为 2，双精度误差的向上取整最大为 1。
单层纯色、透明黑、CPU 帧再注册图片和圆角纯红边缘通过。

视觉复查进一步发现旧 CPU 图片叠加有绿黑竖条，Skia 同场景没有。最小复现是在透明底依次绘制 `(255,0,0,128)` 与 `(255,0,0,1)`：旧直通公式算出 R=256，转 uint8 后变成 `(0,0,0,128)`；独立目标整数模型应为预乘 `(128,0,0,128)`。`alpha_p0_characterizes_straight_channel_overflow` 暂时刻画该旧缺陷，P2 必须替换成目标等式断言，不能保留为兼容要求。此问题由目标预乘累积自然消除，不涉及几何算法变化。

在任何 CPU 算法迁移前新增 `alpha_image_reference.py`，按固定输入、独立 source-over 和圆角距离模型生成整个图片场景的目标参考；已验证参考的 alpha 与 P0 原始帧逐字节相等，因此条纹不是几何/采样偏移。`images`/`upload` 的正确性出口冻结为与该参考逐字节相等，旧帧继续保存作缺陷及性能证据；不得扩大下面的通用 RGB 容差来让条纹差异通过。

冻结规则：CPU 同一几何的迁移前后先归一到预乘；alpha 必须完全相等，
预乘 RGB 每通道最多差 4，超差像素比例必须为 0。八层各次舍入的累计余量用于解释容差，
不允许在 P4 失败时放宽。纯不透明覆写仍要求精确一致；连续暗边、位置或布局漂移即使落在数值界限内也失败。
CPU/Skia AA/字体/阴影差异单列，不套用此 CPU 迁移容差或整帧哈希相等要求。

固定 layers 输入有 8 × 1600 × 840 = 10,752,000 个矩形覆盖候选像素/帧；probe 为整个 1920×1080 或 3840×2160 surface。图片场景为六个 600×600 目标矩形，实际混合还受透明像素与圆角 clip 门控，不能将矩形面积冒充非零混合次数。

优先级判断：透明层叠与每帧转换均有可测成本，适合本项迁移；canonical 场景包含大量不透明覆写和 CPU 局部提交，不能从层叠微基准外推整应用提速。Skia 的文本密集场景主要耗时在绘制，headless 不含窗口转换，属于本项之外的成本。以上均为 before，无速度收益结论。

Skia 三组同样完成 15 个场景/窗口组合，每组三次哈希一致。文本密集 paint p50 为 442.0146 / 442.2928 / 463.8607 ms，layers submit p50 为 17.3520 / 18.8454 / 19.2059 ms；后者存在组间波动，P4 使用交错配对结果归因。窗口输入已为预乘，仍发生一次转换和等尺寸副本；软件表面 R=64 的错误三组均复现。
