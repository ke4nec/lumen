Lumen Control Design · MenuBar Optimization

菜单栏优化设计稿：4 个版本（含动效）

在 docs/lumen-menu-controls-design.md §10.4 既有 MenuBar 视觉（Ghost 栏项 + Tonal 打开态 + 120ms 淡入）基础上，给出四个优化方向候选。四版本共用同一面板规格、键盘/语义契约与「零新增 WidgetType / RenderCommand」不变量，差异集中在栏形态与动效语言；每版含可交互演示与动效参数表（时长/曲线均映射到 core::Tween 与 MotionTokens 既有通道，reduceAnimation 一键归零）。落地建议见文末对比矩阵。

实现状态（2026-09-18）：已按文末建议落地 A + D 组合（menuOpenFadeMs=120 淡入+上升/级联滑入、menuHighlightSlideMs=90 高亮动能矩形、栏 Tonal + 下划线渐入），实现口径见 docs/lumen-self-use-roadmap.md 菜单动效完成记录。实现侧等价表达与取舍：下划线以透明度渐入替代 scaleX 生长（transform 通道未接线）；关闭即时不出场淡出（不延迟命令分发）；激活闪烁未实现；B 列 P2、C 待通道激活。

版本 A · 基线精修 低成本 · 直接落地
保留 Ghost 栏项与 Tonal 打开态 · 新增锚定下划线（120ms 中心生长）· 面板打开 = 淡入 120ms + 6px 上升 EaseOut · 关闭仅淡出 80ms
1
形态：打开态从「仅背景」到「背景 + 位置」 保留 Ghost 栏项与 Tonal 打开态不动，新增 2px accent 下划线锚定打开项（宽度≈栏项文字区，中心生长）——hover 切换时视线跟随下划线即可定位，长栏辨识度提升。
2
动效：升起淡入、关闭不坠落 打开 = fade 120ms（menu.open.fadeMs 既有 token）+ 6px 上升 EaseOut；关闭仅淡出 80ms、无位移——避免「菜单掉下去」的错觉；顶级切换 = 重新锚定并重放打开动效。
3
成本最低 fade 走 transitionAlpha 现成通道（M10）；上升是打开帧内的一次性偏移采样（Tween 持钟）；下划线为栏内单元素重排采样。零新增渲染能力、零新增命令，可直接并入下一版默认行为。

版本 B · 锚点滑移 连续性 · P2 演进
栏指示器 = 单 pill 滑移（160ms EaseInOut）· 面板跨栏连续滑移 + 内容交叉淡入（80ms/80ms）· 打开 = 淡入 140ms + 4px 上升
1
形态：指示器收敛为单 pill 栏项不再逐个换背景——一条 accent-soft pill 在栏项间滑移（left/width 160ms EaseInOut），栏项本体仅文字变 accent-content。栏视觉更轻，「当前在哪」由一个运动元素连续表达。
2
动效：切换不重建面板 Left/Right 或 hover 切换顶级菜单时面板不关闭重开——整体滑至新锚点（160ms EaseInOut），内容交叉淡入（旧 80ms 出 / 新 80ms 入、入延迟 40ms），pill 同步滑移。拖过栏即「浏览」，连续感最强。
3
成本中等，建议 P2 需要 overlay 每帧重定位（setOverlayBuilder 重求值路径）与双层内容透明度——M11 路径全部现成，但连续重排的 damage 口径需要专门打磨与测试。

版本 C · 纵深级联 层级感 · 依赖 transform 通道
面板自锚点左下「生长」（scale 0.96→1 · 150ms EaseOut）· 子菜单上叠 -6px、elevation 逐级 +1、级联延迟 60ms · 栏项 caret 打开时旋转 180°
1
形态：生长方向与锚定关系一致 面板以栏项左下为原点从 0.96 生长到 1（fade 150ms 同步），打开方向即面板来源方向；子菜单上叠父面板 -6px 且 elevation 逐级 +1（L2→L3）——层级表达最强，最接近 macOS 语感。
2
动效：级联时序可读 子菜单 fade 120ms + 12px 右移、延迟 60ms 展开——深层菜单「接续而来」而非同时闪现；栏项 caret 旋转 150°/180° 段作为打开信号。关闭仅淡出 100ms。
3
依赖最强：scale/rotate 通道 scale 与旋转依赖 RenderCommand.transform（v0.2 预留字段，未接线）——需先激活该通道，或以尺寸插值重排近似（成本高、文字缩放失真）；caret 可降级为两态图标（上/下各一帧）。四版本中唯一需要渲染层增量者。

版本 D · 瞬时响应 零延迟 · 键盘重度
内容首帧即现（0ms）· 仅阴影 80ms ramp（L1→L2）· 键盘高亮 = 动能矩形滑移 90ms EaseOut · 栏 hover 不换背景、下划线 0ms 即现
1
形态：为感知延迟做减法 面板内容首帧即现（无淡入），仅阴影在 80ms 内从小档升到 L2；栏 hover 只变文字色不换背景，打开下划线 0ms 即现——高频/键盘用户与低端机上的「点了就到」。
2
动效：集中在「移动的高亮」 键盘/指针高亮 = 一块动能矩形在项间滑移（90ms EaseOut、跨分隔线高度变形，Windows 11 marquee 同源）——视线跟随单元素运动的成本低于逐项闪变；激活 = 高亮闪 120ms 后关闭。
3
成本最低、兼容最好 全部动效 = 单个高亮矩形的重排采样（现成模式）+ 阴影参数插值（DrawShadow 既有）；零新增通道，且天然最接近 reduceAnimation 形态——也可作为 MotionPref「instant」档的实现蓝本。

✅ 已按此建议实现 A+D（2026-09-18）——详见页首实现状态说明。

通道 1 · fade / 透明度（现成）

Widget.transitionAlpha（M10 转场通道）：A/B/C 的淡入淡出、B 的内容交叉、D 的激活闪烁。menu.open.fadeMs = 120 既有先例。

通道 2 · 位移 / 尺寸（现成）

控制器持钟 core::Tween 采样 + 每帧 overlay 重排（setOverlayBuilder 重求值）：上升/右移、B 的 pill 与面板滑移、D 的高亮矩形、A 的下划线。

通道 3 · scale / rotate（预留未接线）

RenderCommand.transform 为 v0.2 预留字段：C 的生长与 caret 旋转需要先激活该通道；尺寸插值重排可近似但有文字失真。

通道 4 · reduceAnimation（既有规则）

MotionTokens::reduceAnimation 全部时长归零、FrameScheduler 不空转（M12 规则）；四版本的动效均只做「表达增强」，不承载信息——归零不损失可用性。
