LUMEN · DESIGNER · TOOLBAR REDESIGN

顶部工具栏重设计 · 四版提案

现状问题：buildToolbar（designer_app.cpp:3644）把 22 个按钮单行平铺、逐钮写死宽度，1280 视口下尾部被裁剪；全部 Filled 变体导致无主次；无分组、无图标，功能只能靠文字识别。本提案保持 registerCommands 的命令与快捷键体系完全不变，只重排表现层：按使用频率定优先级、按功能分组定结构、按 IconId 语言（16px / 描边 1.8）补图标。四版共享同一套图标语义与 CoreDark token。

版本 A · 全功能分组 保守渐进 · 零收纳✔ 已选定并实现（2026-10）

22 个功能全部保持可见，只做三件事：按频率重排（编辑→运行→文件→环境→缩放）、组分隔线划分、低频项去文字改图标 + tooltip。视觉从 22 个 Filled 降噪为 ToolBar chrome 幽灵语言，Run 是唯一 Filled 主按钮。适合不想任何功能被藏起来的使用者。
实现状态：已落地 buildToolbar（designer_app.cpp）；落地时向 token 对齐三处——文本 13px→caption 12px、图标钮 38→40（minHeight 下限）、zoom 重置 50→64（buttonMinWidth 下限），图标进 core::IconId 目录，无文字命令以 semanticsLabel 暴露（UIA/AT-SPI 按名调用不受影响）。

版本 D · 品牌中轴 + 分段环境控件 结构化 · 仪表台

左=品牌（Lumen Designer），中=精选命令带（仅 Add Text / Delete / Save 三个高频命令保留文字，其余图标化），右=运行组 + 环境仪表区：明暗 toggle、密度分段控件（Compact/Comfortable/Touch 一眼可读可直接点选，不再循环）、DPI 循环 chip，其余（字号/对比度/参考线/预览状态）收进齿轮弹层。环境从“一排按钮”变成“可读的当前状态仪表”。

建议：日常自用以 版本 B 为推荐起点（主带可扫读、环境可收纳、留白充足）；若希望零收纳可退 A；追求极致画布空间选 C；等控件库与命令集稳定后再演进 D 的仪表化环境区。四版共享同一图标语义表，选定后图标资产可直接沉淀进 core::IconId 注册表。

落地约束：任何版本都不改 registerCommands 的命令 id 与快捷键；弹层/分段若入选，走框架既有 Menu/Dropdown 控件实现，颜色全部取自 Theme token（本稿 CoreDark 值与 designer-workbench.html 同源）。
