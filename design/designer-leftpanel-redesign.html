LUMEN · DESIGNER · LEFT PANEL REDESIGN

左侧面板重设计 · 四版提案

现状问题（buildOutlinePanel，designer_app.cpp）：37 类节点两列平铺——无分类、无检索，找一个类型要目测扫 19 行；Project / Toolbox / Outline 三段纯堆叠，层次只靠裸标题；Toolbox 固定 240px 高与 Outline 抢空间。本提案重排左栏功能布局，四版共享同一分类法（对齐 examples/gallery 的 nav taxonomy 与 core::IconId Nav 图标资产，不造新控件语言）；插入/拖放命令（designer:toolbox:type）与快捷键体系完全不变。

节点分类法 四版共用 · 37 类 → 7 组

分组口径：布局=容器/排版，内容=静态展示，输入=可交互控件（gallery 的 Buttons+Inputs 合并），集合=数据容器，反馈=状态呈现，组件=L3 复合件（designer 有适配器的 10 类中的 6 类），作用域=行为包装器。组序即插入频率的大致降序。

版本 A · 分组手风琴 分类抽屉 · 保守

Toolbox 从"一堵墙"变成 7 个可折叠分组：组头 = 图标 + 名称 + 数量 + chevron，组内仍是两列幽灵 chip。默认展开布局 + 输入两组（插入频率最高），其余收起；整个 Toolbox 限高滚动，Outline 拿回固定下限。Project 压缩为一行状态（图标 + "No project" + 新建/打开动作）。

结构 Project 行 + 7 组手风琴 + Outline 检索 无（靠分组收敛） 默认可见 布局+输入 17 类 新增机制 折叠组

版本 B · 搜索 + 分类筛选 资产面板 · 效率优先

Toolbox 顶部加搜索框（输入即过滤 37 类，支持前缀/子串）+ 分类 chips 行（全部/布局/内容/输入/集合/反馈/组件/作用域，单选）；命中项仍为两列幽灵 chip，无结果显示"无匹配"。这是资产面板（Figma assets / VS Code palette）的交互模式：分类负责浏览、搜索负责直达。

结构 搜索 + chips + 过滤网格 + Outline 检索 搜索框 + 分类单选 默认可见 全部 37（有筛选） 新增机制 TextField 过滤态

版本 C · 面板页签 Outline ⇄ Toolbox 整栏切换 · 空间最大化✔ 已选定并实现（2026-10）

左栏顶部一组小页签（与中央 Canvas/Source/References 同语言）：大纲 或 工具箱 二选一占据整个 632px 高。工具箱视图 = 7 组全展开的整行列表（图标 + 类型名 + 拖拽把手，行高 26px，19+7 行放得下并可滚）；大纲视图 = 完整高度的树。Project 收成底部状态行。适合"浏览文档结构"与"找组件插入"两种心智不混用的场景。

结构 页签 + 整栏视图 + Project 底行 检索 分组滚动 视图高度 632px 全高 新增机制 面板级 Tabs

建议：A 是结构收益/成本比最高的一步，且可与 B 叠加（手风琴组头上方再加搜索框，组过滤+文字过滤正交）。若大纲是主要工作面选 C；追求零查找选 D。四版共用同一分类法与图标资产，选定后图标直接落 core::IconId（Nav 系列已存在 7 枚中的 5 枚，需补 内容/作用域 2 枚）。

落地约束：分组元数据放 designer_app.cpp 应用层（schema 注册表顺序不变，分类只是展示映射）；designer:toolbox:type 点击/拖放 handler 与拖放 claim 逻辑（attach :1139）零改动；折叠组/页签/搜索分别映射既有控件（Tree 折叠、makeTabs、makeTextField），颜色全取 Theme token。
